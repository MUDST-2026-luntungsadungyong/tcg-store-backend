## Exact test commands and output

### 1. Public health and metric isolation

```text
GET /api/health                  → HTTP 200
GET /actuator/prometheus         → HTTP 404
```

The health response reported `Mythix TCG Backend is running healthy!`,
`total_cards_in_db: 2002`, and `database: Connected`. The metrics response was
generated by the public gateway, proving that Prometheus remains internal-only.

### 2. Bounded load

The load test is deliberately limited to 30 sequential read-only calls, not a
stress test:

```text
endpoint: GET /api/cards?size=1
requests: 30
success:  30
errors:   0
latency:  141.68 ms min / 164.38 ms avg / 228.48 ms max
```

Azure Managed Prometheus scrapes every 30 seconds. After this run, inspect the
Grafana **Request rate** and **Read latency** panels with environment `aks-demo`
selected. The traffic is expected to appear in
`http_server_requests_seconds_count` and
`http_server_requests_seconds_bucket`.

### 3. Controlled 5xx

The invalid `sortBy` query exercises the backend error handler without writing
to the database or changing a deployment. It returned an HTTP 500 at
`2026-11-13T14:18:07Z`; its correlation ID is:

```text
8f2086d8-f9ad-4cf5-bb0f-fabf24a14817
```

Use this KQL query in `law-tcg-store-aks-demo` after ingestion:

```kusto
ContainerLogV2
| where TimeGenerated > ago(2h)
| where PodNamespace == "tcg-store-aks-demo" and ContainerName == "backend"
| where LogMessage has "8f2086d8-f9ad-4cf5-bb0f-fabf24a14817"
| project TimeGenerated, PodName, LogSource, LogMessage
| order by TimeGenerated desc
```

Use this PromQL query in Grafana to confirm the 5xx panel:

```promql
sum(rate(http_server_requests_seconds_count{
  job="tcg-store-backend", environment="aks-demo", status=~"5.."
}[5m]))
```

## Required operator-only completion steps

The following actions change cluster availability or deliver external
notifications. They must be executed from Azure Cloud Shell or another approved
operator workstation, then recorded here with screenshots.

```powershell
az aks get-credentials --resource-group rg-tcg-store-aks-demo --name aks-tcg-store-demo
kubectl get servicemonitor -n tcg-store-aks-demo
kubectl get pods -n kube-system
kubectl rollout restart deployment/tcg-store-backend -n tcg-store-aks-demo
kubectl rollout status deployment/tcg-store-backend -n tcg-store-aks-demo --timeout=5m
kubectl get events -n tcg-store-aks-demo --sort-by=.lastTimestamp
```

After the rollout, verify that the pod is Ready and the public health endpoint
is healthy. A rollout replaces a pod; it must finish Ready before the
environment is considered healthy again. The approved 13 November 2026 restart
was followed by a healthy public response at `2026-11-13T14:35:49+07:00`.

For alert delivery, first deploy an Azure Monitor Action Group and pass its
resource ID as `actionGroupResourceId` when deploying
`infra/observability/azure/aks-demo-prometheus-rules.bicep`. Only then may an
alert rule be fired and delivery to the named email/Teams destination be
verified.
